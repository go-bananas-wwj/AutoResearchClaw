# 调研论文概览与文献上限

2026-10-23：调研概览由配置中的 DeepSeek 模型撰写，程序只负责检索、选择输入材料、调用模型、校验结构与保存结果。系统提示词以 `researchclaw/ideation/prompts.py` 为准，页面“生成方式与提示词”和 `/api/ideation/prompt` 返回同一份实际模板。

## 调用顺序

1. `plan` 理解方向并生成不同用途的中英文检索式。
2. `screen` 只输出论文 ID、核心/邻近/不相关判断及理由，不承担总结任务。排除的论文不因缺少概览而阻断流程。
3. 服务端将候选按相关性排序、兼顾近期与经典工作，尝试获取原文；只有可用原文才能继续解读。
4. `summarize` 只接收可用原文，由 DeepSeek 面向零基础读者写“提出的科学问题、研究意义与研究现状、论文自身创新点、方法、数据、验证效果、优点与缺点”，另外写一段连贯中文总结。同时输出正文相关性、方法与验证依据、推荐或排除理由，附1–2条可逐字核对的短引文。程序不拼接段落，也不以题名构造科学问题或优缺点。
5. 首轮已经阅读原文，页面显示“已读全文 · 概览完成”。用户确认方向后，`read` 再进行更细的方法重建、引文核对和跨论文比较，然后进入缺口分析、构思与独立审查。内部精读记录与首轮概览分开保存，概览不会启动实验。

## 总结提示词的重点

- 科学问题：试图解释、检验的关系或现有方法的具体瓶颈，不复述题名。
- 具体方法：对象、关键机制、数据、对照或论证；按论文实际学科和研究类型理解。
- 优势：证据支持的贡献及成立条件，区分作者主张与比较实验支持的结论。
- 局限：作者明示的假设和验证边界；模型推断必须标明，根据材料缺失不能断言论文没做。
- 用短句、普通词解释，必要术语首次出现要解释，不堆缩写、公式和参数。原文未报告时如实说明，不强迫模型编出优缺点。
- `summary_zh` 是模型独立撰写的约 120–200 字连贯中文，原样保存，不由程序重组四个字段。

只使用缓存原文全部页面（至少2,000字符），取消18万字符固定上限。未获取全文、只有摘要时，不生成摘要替代概览，不展示为入选文献；原始候选及获取失败记录保留在后台。候选范围内会尝试替补，数量不足如实展示；零篇合格全文时暂停，指定论文缺少正文时也不能跳过。

正文检查区分 direct/supporting/off_topic 相关性和 strong/adequate/weak/unclear 方法依据。只有 direct/supporting 且 strong/adequate 能入选；这表示是否适合本轮研究，不是权威论文评级。方法与验证应按学科理解，理论证明、实验、观测和系统综述都有合理形式。引用量与年份只作辅助，不以期刊、机构或高引用替代正文判断。模型从完整正文中选择支持判断的片段编号，服务端据此附上实际页码和原文；未知编号、跨论文引用均拒绝。正文按顺序无损分段，切分不删改、不总结，避免让模型重新抄写引文时改写内容或发明页码。旧格式的短引文仍做长度与逐字匹配校验，只有同篇唯一逐字匹配时才能纠正位置。最终排序优先直接相关与正文方法依据，再兼顾近期、经典覆盖。

每个概览字段由模型写成1–2个短句，目标60–100字、硬上限160字符。超长内容退回模型重写，程序不裁剪或重组科学总结。八个字段由模型分别撰写；页面把方法、数据、效果组织在“方法”部分，不以改标题冒充新的内容。技术精读笔记单独保留，后续证据核对不覆盖通俗解读。

每次概览或阅读请求只含一篇论文，发送独立的system与user消息，不携带其他论文或历史对话。完整字段与论文身份未通过校验时给模型一次针对性修正机会，不使用默认文本补齐。JSON 格式与截断重试沿用统一模型调用守卫，所有尝试计入预算。对于真实调用中出现的 `summary_zh` 后漏掉结构逗号，只允许在解析器明确定位到已知 `selection` 字段时补一个逗号；另可在字符串/转义感知的括号栈上移除最多3个多余结束括号。之后仍进行严格 JSON、完整字段与证据校验，不改字符串、不补事实、不补缺失的结束结构，其他损坏退回模型或暂停。材料与提示词哈希记录在论文上；正常恢复会跳过已完成且依据未变的概览，用户手动更新则重写尚未进入后续证据核对的概览。新增论文必须重新整理全文；入选范围变更时提升版本并使旧批准与卡片失效。再次获取原文成功后，也会按新材料更新概览。

## 文献数量与状态

新会话默认入选上限 20 篇，页面可选 10、20、30 篇；API 接受 3–30 篇。检索候选最多为入选上限三倍，且最多 60 篇。查询间分配候选名额、去重后筛选，不以篇数要求补入无关论文。已批准的旧会话范围保留，未批准的旧会话恢复时采用默认上限；超出候选上限的旧条目单独归档。

页面仅把已筛选且入选的论文计为相关文献，不再将未筛选条目计入。检索式、筛选、下载、模型概览、精读分别显示各自状态；方向确认前显示全文阅读和概览状态，确认后另行显示原文依据核对进度。

精读数量沿用默认 10、最多 15 篇。全文可用性、文献真实性、两轮人工审核及阶段 9–23 的交接约束保持生效。

## 对齐用户提供的科研工作流

依据用户在2026-10-23粘贴的《AI科研工作流：文献检索、论文复现与实验迭代》相关段落：先建立领域地图、保存论文多种材料、优先重视可验证的方法和重要工作、由用户把握方向与创新点。Mac原文件未直接读取，采用用户粘贴内容作为参考。

新流程对4–6条检索式分配经典、综述/主题和近期入口。经典OpenAlex检索使用主题条件加引用次数降序，不设起始年份；引用量用于召回，不直接作为质量结论。近期检索保留近两年范围。直接检索预留至多12个候选名额用于引用扩展；在已筛出的核心论文中固定最多3篇种子，兼顾高引用与近期，追踪其参考文献及后续引用。扩展结果也须去重、相关性筛选、获取全文和正文检查，仍受60篇候选总上限约束。种子与完成记录持久化，恢复时不会沿新种子无限递归。经典/引用路径使用已有检索缓存；零结果不缓存为成功。

当前已确认的旧会话范围按原版本继续；新策略用于新建或明确重新调研。页面“这些文献是怎么找到的？”显示本轮实际查询、取得结果的来源、候选数、入选数与年份，并区分已有检索记录与增强策略，不追认旧记录已经做过引用扩展。

在会话 `related work/` 目录保存每篇的可用PDF、完整提取文本与JSON索引，记录格式和相对路径。提取文本不是LaTeX源码，`latex_source` 未取得时为空。交接科研时一起复制该材料目录，沿用已有复现、任务书、实验验证与版本管理。

该部署按用户要求取消美元预算上限：`hitl.cost_budget_usd=0`，`experiment.cli_agent.max_budget_usd=0`。会话仍保存每次调用的用量与保守预留记录，不把预留当实际账单；旧会话在恢复或更新时同步不限预算设置。质量、证据、取消、输出长度及自动修订轮数等检查继续生效。


## 本轮真实材料核查与修复

更新解读时发现，两篇旧缓存只有摘要/题录，却因网页够长且出现“方法”一词被早期逻辑标成全文。现在HTML必须有实质的正文章节与段落，落地页不合格时继续跟踪真实PDF；旧缓存隔离保存。PDF和HTML的前部正文还须匹配请求论文的题名、DOI或arXiv编号；不能把参考文献或相似文章的PDF错误关联给该论文。用户上传PDF可依据服务器核验过的原始内容哈希绑定身份。摘要页即使有方法描述、参考文献且内容哈希一致，也不能复用为精读证据或通过创新点确认。

核查的两篇中，一篇取得10页PDF但为扫描图像、文本提取为空；另一篇页面里的PDF链接实际指向参考文献中的另一篇论文，已拒绝关联。最终保留18篇正文可读且身份匹配的文献，原始60篇检索记录保留，旧审核与11篇有效核对记录保存在历史快照。文献范围变化使旧批准、综合与候选失效，返回方向确认；修复范围由服务端18个论文ID固定，不为补足20篇加入新的未审核论文。

DeepSeek官方支持JSON Output。本地客户端现在只对官方端点启用 `response_format={"type":"json_object"}`；第三方代理继续使用原有兼容回退。依据：[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。

经典排序与引用扩展依据：[OpenAlex API recipes](https://help.openalex.org/how-to/api-recipes/)、[Citations](https://help.openalex.org/data/works/citations/)。真实接口实测能召回1988、2000等早期文献，扩展结果仍须重新筛选，不能因高引用或来自引用链而直接入选。


## 长论文独立上下文与领域图景排版（2026-10-24）

官方DeepSeek端点的当前V4系列支持1M tokens上下文，参见[官方模型说明](https://api-docs.deepseek.com/quick_start/pricing/)。服务端按UTF-8字节保守估算输入、扣除系统提示词、输出与安全余量；字符不是token。单篇156页、约33万字符不再触发旧18万字符暂停。其他端点保守使用128K。

原文超出一次请求容量时，自动按实际页码无损分段，DeepSeek逐段阅读，再仅合并同一篇论文的阅读记录。包含方法证据的最终记录通过后才可进入创新审查。片段引用由模型选择本篇原文ID、服务器附回原文和位置；显式提供的虚构引文仍拒绝。`reading_parts/<paper_id>/<source-and-prompt-hash>/` 保存每段与汇总检查点，重试跳过已完成调用，材料/提示词变化会重新计算。每次用量记录保存单篇ID、输入字节与上下文容量；预审核长文内部阅读不会自动批准文献或登记科研项目。

概览与精读均逐篇隔离；跨论文只在后续领域综合、创新构思及最近邻审查阶段比较已有阅读记录与选定原文证据，不再把多篇完整正文拼成审查请求。长文自动处理不需要用户制作短版，不放宽全文身份、方法证据和人工创新点审核。

领域图景由模型输出简短概述、研究路线、方法对照与待验证问题。界面展示分节卡片、论文来源按钮和可横向滚动的方法表格；完整分析默认折叠。旧会话直接使用已有方法对照与缺口字段呈现，原分析文本完整保留，程序不编写或重组科学总结。

实测：现有调研中的《Developing new multi-image InSAR methods for atmospheric delay estimation》是156页博士论文。约33万提取字符完整进入单篇请求，DeepSeek实际输入110,578 tokens，返回结构化阅读记录及3条方法原文证据；coverage记录完整处理331,987个非空片段字符、一次请求。原文总字符中仅空白片段不发送。18篇首轮概览也已改为逐篇独立请求更新，已批准范围保持原版本。

本轮测试覆盖长文完整传入、超窗口自动分段、独立上下文拒绝混篇、逐段检查点与新服务实例恢复、材料改变使检查点失效、预审核长文解读不批准文献、最近邻审查只比较笔记与原文证据、结构化路线ID还原。页面使用真实会话的只读jsdom检查方法表格、来源弹窗、问题卡片及折叠完整分析；结构化路线和转义另用隔离数据验证，未完成原生浏览器视觉验收。
